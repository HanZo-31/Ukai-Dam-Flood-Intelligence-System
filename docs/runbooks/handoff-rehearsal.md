# Step 14 — clean local B1 handoff rehearsal

Local engineering rehearsal completed 2026-10-05. This is a B1 technical
handoff gate, not the blueprint's joint backend/scientific acceptance gate.

## Reproduce safely

With the existing local Docker PostgreSQL/PostGIS healthy, run from the project
root using the verified Python environment. Use a new output name every time:

```powershell
.\.venv\Scripts\python.exe scripts\rehearse_b1_handoff.py --output data\handoff\b1-new-timestamp
```

The script accepts only a new directory under data/handoff. It uses a generated
`b1_handoff_<uuid>` database, never restores over the working database, and
removes the generated database in cleanup. It retains files and evidence for
review. Do not run this beside application writes: before/after working snapshots
must match, including ID sequences and all working object hashes.

## What it does

1. Copies an explicitly allowed source set: database, services, scripts, tests,
   docs, README, requirements, Compose, Alembic, pytest config and .env.example.
   No private .env, live data, Git history or virtual environment is copied.
2. Creates an empty database from template0 and enables PostGIS; applies ALL
   migrations using the source copy and checks model/schema parity.
3. Runs the seed twice and checks identical rows, sequences and files.
4. Runs the full regression suite from the source copy against the fresh seeded
   database. Test discovery is restricted to tests/; runtime bytecode/cache writes
   are disabled so copied source hashes stay stable.
5. Generates real synthetic COG/GeoJSON files, validates metadata/GIS, registers
   demo datasets/versions, a clearly synthetic event and a supplied demo metric.
6. Imports one draft, one synthetic historical replay and three hypothetical
   fixture scenarios through the actual default CLI. The four review labels are
   TEST-ONLY approval declarations, not hydraulic/scientific approval. They reuse
   synthetic GIS files to test catalog relationships, not distinct flood models.
7. Checks catalog, details, four layers, nullable impacts, provenance, extent,
   spatial assets, dataset/time/model filters, paging, event catalog and demo status.
   Draft/wrong-mode results remain hidden. Duplicate/bad-checksum imports fail
   without changing the database snapshot.
8. Revokes one hypothetical fixture; all public reads hide it while the original
   snapshot/audit remain. B2 HTTP endpoints are not involved.
9. Performs an actual populated pg_dump/pg_restore verification of 16 tables,
   PostGIS, hashes, sequences, spatial metadata and local artifact references.
10. Verifies source-copy integrity and working-data preservation, saves evidence,
    and deletes only the exact generated rehearsal database.

## Evidence package and acceptance

Read rehearsal.json: result must be passed; every step passed; working_data_preserved
and disposable_database_removed true. clean_suite_summary records the full suite.
backup/restore-check.json must show PostGIS and the complete table inventory,
with no unresolved external references for this clean fixture.

source/ is the dated code snapshot. objects/ retains synthetic files and CLI
manifests (including the intentionally invalid rejection fixture); backup/ is the
matching verified DB/object archive. Do not mistake the intentionally invalid
manifest for an approved example. Stored hashes detect drift, not authenticity.
Only trusted archives may be restored.

Latest finalized audited package: data/handoff/b1-final-audit-20261005-03/. Earlier iterations
are retained for traceability, including the first failed source-integrity check
caused by generated bytecode, and an interrupted post-restart connection attempt.
Use the finalized passed package for handoff. Local connections now normalize
localhost to IPv4 with a default five-second connection timeout.

The snapshot does not contain a working .env. B2 creates private configuration
for its own local environment; never send the working project's .env. Internal
absolute file:// URIs are local catalog references, NOT public API URLs. On a
different host regenerate the fixture/rehearsal, or review URI remapping before
restoring the package; do not blindly point B2 at the recorded former temp DB.

## Explicit limits

- Reuses the installed Docker server and existing Python 3.13 environment.
  A new-host Docker build, fresh dependency install and Python 3.12 validation
  are not performed. The blueprint names 3.12; agree the supported runtime with
  B2 or separately verify 3.12 before claiming strict blueprint compatibility.
- No real Team A bundle, scientific pass thresholds or reviewer authentication.
- No B2 FastAPI/OpenAPI/asset-serving or end-to-end HTTP acceptance.
- No Git/CI, production deployment, remote storage adapter, automatic backup
  scheduling, independent/off-host copy or recovery promotion.
- Current GIS accepts the formats in contracts/spatial-gis-catalog.md; KML,
  rotated/multiband grids and other unsupported formats need agreed scope/adapters.
